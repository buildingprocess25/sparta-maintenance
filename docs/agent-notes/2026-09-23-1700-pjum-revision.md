# PJUM Revision Feature

## Scope

Added functionality for Managers to request revisions for PJUMs (status `REJECTED` -> "Direvisi") and for BMCs to edit and re-submit (Submit Ulang) a revised PJUM. Added a historical record (`revisionHistory`) of all revision notes provided by Managers, ensuring visibility on both sides.

## Context and Sources

- `schema.prisma`: Added `revisionHistory` JSON field to `PjumExport`.
- `lib/pjum-status.ts`: Updated `REJECTED` status to render as "Direvisi" (orange badge).
- `app/dashboard/pjum/actions.ts`: Added support for bypassing existing `pjumExportedAt` during search, and created a new action `updateDashboardPjum` for re-submitting edited PJUMs.
- UI Components: Detail Page `PjumRevisionButton`, `CreatePjumDialog` in Edit mode.

## Changed Files

- `prisma/schema.prisma`: Added `revisionHistory` to `PjumExport`.
- `lib/pjum-status.ts`: Changed `REJECTED` label to `Direvisi`.
- `app/dashboard/pjum/page.tsx`: Filter and metrics updated to include `REJECTED`.
- `app/dashboard/pjum/actions.ts`: Added `editingPjumId` to search action and created `updateDashboardPjum`.
- `app/reports/pjum/approval-actions.ts`: Updated `rejectPjumExport` to append revision log.
- `app/dashboard/pjum/[id]/page.tsx`: Added UI for the history alert, revision button, edit button, and missing data displays.
- `app/dashboard/pjum/_components/create-pjum-dialog.tsx`: Added edit mode capabilities (`editingPjum` props).
- `app/dashboard/pjum/[id]/_components/pjum-revision-button.tsx`: Created new revision modal form for Managers.

## Decisions

- Store history directly on the `PjumExport` record as a JSON array (`revisionHistory`) to simplify schema and avoid creating a dedicated history table since only a few simple string fields (`date`, `actorName`, `note`) are needed.
- `updateDashboardPjum` bypasses typical hanging report and existing association rules *only for* the current `editingPjumId`, avoiding "Laporan sudah masuk PJUM" validation errors when the user keeps the same reports checked.
- Kept the UI intuitive by reusing `CreatePjumDialog` for the Edit flow to avoid code duplication and maintain visual consistency.

## Verification

- `npx tsc --noEmit` runs to check TS types.
- Evaluated `updateDashboardPjum` policy execution paths to ensure mandatory hanging reports cannot be easily dismissed by unchecking them during edit.
