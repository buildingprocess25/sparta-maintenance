## Scope

Added caching for `getAdminBranchHierarchy()`.

## Context and Sources

- Branch hierarchy is queried frequently and builds an extensive map from the entire user base.
- Following the `docs/superpowers/plans/2026-09-28-db-pool-optimization.md` plan.

## Changed Files

- `app/dashboard/queries.ts`: Wrapped `getAdminBranchHierarchy` logic inside `unstable_cache`. Converted Map to array of entries before caching because Next.js `unstable_cache` requires serialization, then rehydrates the Map on cache hit.

## Decisions

- **Unstable Cache:** Used Next.js `unstable_cache` with a 10-minute revalidation interval and `branch-hierarchy` tag.
- **Cache Invalidation:** Added `revalidateBranchHierarchyCache` helper. Note: User mutations seem to be managed via background sync or external scripts, so there were no local `createUser`/`updateUser` Prisma mutations found to attach the invalidator to. It will expire gracefully every 10 minutes.
