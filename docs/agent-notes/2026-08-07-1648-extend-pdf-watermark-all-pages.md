# Extend PDF Watermark to All Pages, Swap Logo to sparta-maintenance.png

## Scope

Extend the SPARTA watermark to cover all PDF documents generated by the system — not just the PJUM Form (pertanggungjawaban uang muka) page. Also swap the watermark logo from `Building-Logo.png` to `sparta-maintenance.png` across all PDF generators.

Outside scope: changing logo references in the web UI header, sidebar, email templates, and other non-PDF contexts.

## Context and Sources

- Feature branch: `feature/pjum-pdf-enhancements`
- Prior work: watermark was already added to `generate-pjum-form-pdf.ts` (PJUM form page) in earlier commits on this branch.
- User request: extend watermark to all PDF pages; use `public/assets/sparta-maintenance.png` as logo.

## Changed Files

- `lib/pdf/generate-pjum-form-pdf.ts`: Swap logo to `sparta-maintenance.png`. Remove unsupported `zIndex` and `transform: rotate` from watermark style (these caused a react-pdf render error — rotation to be revisited).
- `lib/pdf/generate-pjum-package-pdf.ts`: Swap logo to `sparta-maintenance.png`. Pass `watermarkLogoBase64` to `generatePjumPdf()` call so recap page also receives the watermark.
- `lib/pdf/generate-pjum-pdf.ts`: Add `Image` import, add watermark styles (`watermarkContainer`, `watermarkImage`, `watermarkText`), add `watermarkLogoBase64?: string` to `PjumPdfData` type, render watermark element on the recap page.
- `lib/pdf/generate-report-pdf.ts`: Add watermark styles, add watermark element on the report PDF page using existing `data.buildingLogoBase64`.
- `lib/pdf/report-pdf-builder.ts`: Swap logo from `Building-Logo.png` to `sparta-maintenance.png` so the report PDF header and watermark both use the new asset.
- `public/assets/sparta-maintenance.png`: Added to repo as new asset.

## Decisions

- **`transform: rotate` removed for now**: The `@react-pdf/renderer` v4.x `transform` property caused a render crash (`TypeError: Cannot read properties of undefined (reading 'S')`) during local testing. Root cause was not fully isolated (could be tsx environment vs Next.js runtime difference). Rotation removed to ensure correctness. Can be re-added and validated in a proper Next.js server environment.
- **`zIndex` removed**: Not supported by `@react-pdf/renderer`; removed to avoid warnings.
- **Logo used for report PDF watermark**: `buildingLogoBase64` in `generate-report-pdf.ts` comes from `report-pdf-builder.ts` which now loads `sparta-maintenance.png`.
- **Other `Building-Logo.png` references not changed**: References in UI components and email templates are intentionally left unchanged — they serve a different purpose.

## Verification

- Git diff reviewed manually for all changed files.
- Local script test (`npx tsx --conditions react-server`) confirmed PDF generation reaches `renderToBuffer` stage before failing on an unrelated react-pdf environment issue (not caused by our changes — original `main` branch code exhibits same error in this runner).
- Full integration testing must be performed via the actual Next.js approval flow.

## Remaining Work and Risks

- **Rotation effect**: `transform: rotate(-30deg)` was removed from all watermark styles. If desired diagonal watermark is required, it must be re-validated in the Next.js runtime (not tsx runner) before re-adding.
- Manual test needed: trigger full PJUM approval flow → verify watermark appears on all PDF pages (PJUM form, PJUM recap, and report PDFs).
