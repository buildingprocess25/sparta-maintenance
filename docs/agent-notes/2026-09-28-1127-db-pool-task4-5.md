# DB Pool Optimization - Task 4 & 5

## Scope

Consolidated multiple parallel `prisma.report.count()` queries into single `prisma.report.groupBy()` queries for `getUserStats`, `getBMCStats`, and `getBNMStats`.

## Context and Sources

- These functions previously used `Promise.all` to fire 3-6 queries concurrently per page load, causing connection pool exhaustion under load.
- Following the `docs/superpowers/plans/2026-09-28-db-pool-optimization.md` plan.

## Changed Files

- `app/dashboard/queries.ts`:
  - `getUserStats`: Replaced 6 parallel counts with 1 `groupBy` on `status`.
  - `getBMCStats`: Replaced 4 parallel counts with 1 `groupBy` on `status`.
  - `getBNMStats`: Replaced 3 parallel counts with 1 `groupBy` on `status`.

## Decisions

- **GroupBy approach:** Using `groupBy` shifts the counting burden to a single fast PostgreSQL query, then JavaScript iterates over the results to bucket the statuses as needed.
- **Connection savings:** This saves ~10 database connections per user when a BMS and BMC load their dashboard simultaneously.

## Verification

- Return types remain identical so downstream consumers do not need updates. Visual inspection confirms logic maps correctly to previous discrete counts.

## Remaining Work and Risks

- None.
